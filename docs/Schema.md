# Schema.md — Data Schema (Cloud Firestore)

All data lives under the signed-in owner: `shops/{uid}/...` (PS-8). `uid` = Firebase Auth uid. Examples use **fictional** data only. Money = integer BDT. Timestamps = Firestore `Timestamp` (server time). `dateKey` = `"YYYY-MM-DD"` in **Asia/Dhaka** (D-15).

## 1. Entities and relationships
shop (1) → products, customers, suppliers (many) · customer → ledger entries · sale → items (embedded) → product · sale (baki) → ledger credit · purchase → supplier · aiActions record AI proposals.

## 2. Collections

### `shops/{uid}` (document)
| Field | Type | Req | Validation |
|---|---|---|---|
| shopName | string | yes | 1–60 chars |
| ownerName | string | yes | 1–60 |
| phone | string | yes | BD mobile, 11 digits starting `01` (ASM: format check only) |
| createdAt | timestamp | yes | server |
| demoLoaded | bool | no | default false |

### `products/{productId}`
| Field | Type | Req | Validation / default |
|---|---|---|---|
| name | string | yes | 1–60 (Bangla or English) |
| aliases | string[] | no | ≤5 items, ≤30 chars each (e.g., "chini") — helps Banglish matching |
| unit | string | yes | `kg`,`piece`,`packet`,`litre` |
| buyPrice | int | yes | 0–10,000,000 |
| sellPrice | int | yes | 0–10,000,000 |
| stockQty | number | yes | ≥0 normally; decimals ≤3 for kg/litre, integer for piece/packet; may become negative only through explicitly accepted sale (flagged) |
| lowStockAt | number | yes | ≥0 |
| active | bool | yes | default true (archive = false) |
| isDemo | bool | no | default false |
| createdAt, updatedAt | timestamp | yes | server |

### `customers/{customerId}`
name (1–60, req) · phone (11-digit BD, req) · note (≤200, optional, **never sent to Gemini**) · active (bool) · isDemo · createdAt. **No stored balance field.**

### `sales/{saleId}`
| Field | Type | Notes |
|---|---|---|
| dateKey | string | Dhaka date |
| createdAt | timestamp | server |
| items | array (1–50) of `{productId, name, qty, unitPrice, unitCost, lineTotal}` | `unitCost` = product `buyPrice` snapshot (D-16); `lineTotal = round(qty × unitPrice)` |
| total | int | = Σ lineTotal (code-computed; rules check equality) |
| paymentType | string | `cash` \| `mobile_banking` \| `baki` (bKash/Nagad are labels in an optional `paymentLabel` ≤10 chars) |
| customerId | string \| null | required when `baki` |
| createdBy | string | `manual` \| `ai` |
| negativeStockAccepted | bool | default false |
| aiActionId | string \| null | |
| isDemo | bool | |

### `ledger/{entryId}` (baki)
customerId (req) · type `credit`\|`payment` · amount int >0 · relatedSaleId string\|null · dateKey · createdAt · note (≤200) · createdBy `manual`\|`ai` · aiActionId · isDemo. **Append-only** (see rules).
**Customer balance = Σ(credit.amount) − Σ(payment.amount)**, computed in code. Negative result = customer advance (shown as "advance").

### `suppliers/{supplierId}` (P2) — name, phone, active, createdAt.
### `purchases/{purchaseId}` (P2) — supplierId, items[{productId,name,qty,unitCost,lineTotal}], total int, paid int (0..total), dateKey, createdAt. **Supplier due = Σ(total − paid) − later supplier payments** (a small `supplierPayments` list or ledger-type doc; Antigravity decides in P2 and updates this file).
### `expenses/{expenseId}` — category `rent|electricity|transport|salary|other`, amount int>0, dateKey, note ≤200, createdAt, createdBy, isDemo.
### `aiActions/{actionId}` (P1 optional)
| Field | Notes |
|---|---|
| originalText | what the user typed/said (owner-only, ≤500 chars) |
| functionName | e.g., `proposeBakiEntry` |
| args | validated args (no secrets) |
| status | `proposed` \| `confirmed` \| `cancelled` \| `failed` |
| createdAt, resolvedAt | timestamps |
| resultDocIds | ids of written docs |
Doc id = `proposalId` generated by the app (UUID).

## 3. IDs and idempotency
Manual records: Firestore auto-IDs. **AI-confirmed writes use the `proposalId` as the document ID** inside a transaction that first checks existence → double-tap/retry/refresh cannot create duplicates.

## 4. Example records (fictional)
```json
{ "name": "Sugar (চিনি)", "aliases": ["chini"], "unit": "kg", "buyPrice": 110, "sellPrice": 130, "stockQty": 50, "lowStockAt": 10, "active": true }
{ "dateKey": "2026-11-07", "items": [{"productId":"p1","name":"Sugar (চিনি)","qty":3,"unitPrice":130,"unitCost":110,"lineTotal":390}], "total": 390, "paymentType": "baki", "customerId": "c1", "createdBy": "manual" }
{ "customerId": "c1", "type": "credit", "amount": 390, "relatedSaleId": "s2", "dateKey": "2026-11-07" }
{ "customerId": "c1", "type": "payment", "amount": 200, "relatedSaleId": null, "dateKey": "2026-11-07" }
```

## 5. Indexes
Single-field range queries need none. Likely composite: `ledger (customerId ASC, createdAt DESC)`, `sales (customerId ASC, createdAt DESC)`. **Create only from the console error link when a query actually fails**; record them in `HANDOVER.md`.

## 6. Lifecycle and deletion
Products/customers: archive (`active=false`), never hard-delete (D-14). Sales/ledger: append-only. Exception: documents with `isDemo == true` may be deleted by the owner ("Remove demo data"). No account deletion (P3).

## 7. Integrity constraints (enforced in code **and** rules where feasible)
Positive integer amounts; qty > 0; `total` equals Σ lineTotal; `baki` sale requires `customerId`; `createdBy ∈ {manual, ai}`; string max lengths; `uid` path equals `request.auth.uid`; no unknown top-level fields on create (rules `keys().hasOnly(...)`).

## 8. Security Rules requirements (spec — Antigravity writes the rules file in Phase 3)
| Requirement | Layer |
|---|---|
| Default deny everything | Rules |
| `read, write` on `/shops/{uid}/**` only if `request.auth != null && request.auth.uid == uid` | Rules |
| On create/update of products, customers, sales, ledger, expenses, aiActions: field allowlist, types, ranges and string lengths as above | Rules |
| `ledger` and `sales`: `update` and `delete` denied unless `resource.data.isDemo == true` (delete) | Rules |
| `ledger.amount` int > 0; `sales.total` equals Σ items (if expressible; otherwise code + test) | Rules/code |
| No client write of another uid path, no collection group reads | Rules |
| Multi-document consistency (stock vs sale vs ledger) | Code (transaction) |
| Tested with **two accounts** and the Rules Playground/emulator; results recorded in `Testing.md` | QA |
